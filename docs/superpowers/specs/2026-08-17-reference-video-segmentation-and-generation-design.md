# AdFlow 参考视频分段编辑与 Seedance 生成设计规格

**状态：** 已确认

**日期：** 2026-08-17

**范围：** 提示词方向升级、长视频分段、参考视频生成闭环

## 1. 目标

AdFlow 从“根据原视频生成完整画面描述”升级为“以原视频为最高优先级参考，生成局部编辑指令并提交 Seedance”。系统保留现有素材上传、时间轴校正、逐镜理解、事实确认、提示词版本、任务恢复和本地结果机制，只扩展与本目标直接相关的部分。

用户最终提交给 Seedance 的输入为：

- 一段不超过安全时长的原视频物理片段；
- 该片段对应的编辑指令；
- 已确认并命名用途的产品参考图；
- 按需包含的人物或背景参考图；
- 音频生成设置。

## 2. 术语与核心语义

### 2.1 分镜

分镜是视频内容分析单位，对应现有时间轴中的 `Shot`。每个分镜保存原视频绝对起止时间和已确认事实。

### 2.2 生成片段

生成片段是 Seedance 提交单位。一个生成片段通常包含多个连续完整分镜。生成片段不是分镜，不能把“每段独立生成”解释为“每个分镜独立生成”。

只有单个分镜本身超过安全时长、且镜头边界无法提供合法方案时，才允许从分镜内部切开。

### 2.3 生成任务

每个生成片段对应一个独立 Seedance 生成任务。任务继承现有幂等、租约恢复、供应商轮询、不明确提交人工解析和本地结果下载机制。

例如 32 秒、7 个分镜的视频，可以拆为两个生成片段：第一个包含分镜 1–3，第二个包含分镜 4–7；系统创建两个生成任务，而不是七个任务。

## 3. 非目标

第一版不实现：

- 每个分镜单独提交 Seedance；
- 自动拼接多个生成结果；
- 自动判断生成画面质量；
- 为分段引入新的队列或状态管理框架；
- 重做现有五步页面结构；
- 静默裁掉原视频内容。

自动拼接延后，因为不同生成片段的产品角度、人物位置、色彩、音频和首尾运动可能不连续。第一版先提供逐段对比、播放和下载。

## 4. 分段规则

### 4.1 默认规则

- 单段安全上限为 29 秒，作为提交前硬限制。
- 推荐最短片段为 8 秒，作为可人工覆盖的软限制。
- 原视频不超过 29 秒时保持为一个生成片段，不执行物理裁切。
- 原视频超过 29 秒时自动规划为 N 个生成片段。
- 30–60 秒视频通常得到两段；更长视频根据安全上限自然增加段数。
- 所有原视频内容必须被连续、无重叠、无空洞地覆盖。
- 系统不得为了满足限制而丢弃头部、尾部或中间内容。

原视频总时长本身低于 8 秒时，单段自动合法，不要求用户确认“短片段”。只有拆分操作产生低于 8 秒的片段时才需要明确接受。

29 秒是本地安全值，不等同于永久声明供应商上限。后端用三个普通配置值计算限制，不建立供应商能力表：

- `provider_max_reference_seconds = 30`
- `segment_safety_margin_seconds = 1`
- `recommended_min_segment_seconds = 8`

有效上限为供应商上限减去安全余量，当前结果为 29 秒。前端显示服务端返回的有效限制，不重复硬编码。若真实接口限制变化，只调整后端配置。

### 4.2 自动规划

自动算法按以下优先级选择切点：

1. 保证每段不超过 29 秒。
2. 优先使用已确认时间轴的分镜临界点。
3. 在合法方案中尽量减少生成片段数量。
4. 在相同段数下尽量均衡各段时长。
5. 避免产生低于 8 秒的短尾段。
6. 只有不存在合法分镜边界方案时，才选择分镜内部切点。

例如 32 秒视频不得机械切成 29 秒与 3 秒；系统应在邻近中点的合法分镜边界产生两个较均衡片段。

### 4.3 手动调整

用户可以：

- 修改生成片段数量；
- 增加或删除切点；
- 将切点移动到其他分镜临界点；
- 输入精确时间执行分镜内部切分；
- 恢复系统自动方案。

手动移动默认吸附到最近分镜临界点。分镜内部切分必须由用户明确选择，并显示连续性风险提示。

### 4.4 校验

提交提示词生成或视频生成前，服务端必须验证：

- 所有片段按位置有序；
- 第一段从 0 开始，最后一段覆盖视频结束；
- 相邻片段首尾精确衔接；
- 不存在重叠或空洞；
- 每段大于 0 且不超过 29 秒；
- 分段来源仍是项目当前时间轴版本；
- 低于 8 秒的片段已被用户明确接受。

前端即时显示校验结果，但服务端是最终权威。

## 5. 数据设计

新增生成片段实体，职责仅为保存一个可版本化的分段方案。最小字段：

- `id`
- `project_id`
- `plan_version`
- `position`
- `source_start_sec`
- `source_end_sec`
- `start_boundary_type`：`video_edge`、`shot_boundary` 或 `inside_shot`
- `end_boundary_type`：`video_edge`、`shot_boundary` 或 `inside_shot`
- `source_timeline_revision_id`
- `short_segment_accepted`
- `created_at`

同一 `plan_version` 下的记录组成完整分段方案。用户修改方案时创建新版本，不原地覆盖已经被提示词或生成任务引用的旧方案。

首段起点和末段终点使用 `video_edge`。相邻片段共享同一个切点，因此前一段的 `end_boundary_type` 必须与后一段的 `start_boundary_type` 一致。

`PromptRevision` 增加：

- `prompt_mode`：新工作流固定为 `reference_video_edit`；
- `generation_segment_id`：指向对应生成片段；
- 原视频绝对时间与片段相对时间的快照信息。

`Generation` 增加 `generation_segment_id`，由此明确一个任务对应哪个生成片段。旧提示词和旧生成记录允许字段为空，继续作为历史记录读取。

## 6. 提示词方向升级

### 6.1 输出目标

新提示词不再完整复述原视频，而是依靠参考视频保留原始内容，只表达差异。每个生成片段有一份独立提示词，提示词内部继续按其所含分镜的时间范围组织。

每个分镜固定包含：

- `保持`：人物、动作、手部位置、背景、构图、运镜、节奏等不可改变内容；
- `修改`：产品替换或用户要求的局部改编；
- `删除`：原字幕、贴纸、水印或明确要求删除的元素；
- `禁止`：不得新增、改变或重排的内容。

示例：

```text
00:03.47–00:05.47

保持：
人物身份、动作节奏、手部位置、背景、构图、镜头运动和原片时长不变。

修改：
仅将人物手中的原产品替换为目标产品。产品外形、包装颜色、瓶盖和比例必须匹配对应参考图。

删除：
删除原视频中的字幕、贴纸、品牌文字和水印。

禁止：
不得新增人物、改变动作、改变场景、重排镜头或生成任何可见文字。
```

### 6.2 时间语义

数据库保留每个分镜的原视频绝对时间。提交给 Seedance 时，提示词使用当前物理片段内部的相对时间。

例如原视频 18–21 秒的分镜位于 16–32 秒的生成片段内，提交时间写为 2–5 秒，同时保存绝对时间 18–21 秒用于追溯。

若一个超长分镜被内部切点分到相邻两个生成片段，该分镜允许同时出现在两份编辑指令中，但每份只能覆盖本物理片段内的交集：

- 前一段只描述切点之前的动作，并注明动作延续至片段结尾；
- 后一段只描述切点之后的动作，并注明动作从片段开头承接；
- 两段继承同一份已确认分镜事实，但不得写入本片段范围之外的时间或动作；
- 两段分别转换为各自片段内的相对时间。

### 6.3 生成与验证

采用“服务端固定骨架，GPT 填写差异”的方式：

1. 服务端写入全局保持、替换和禁止规则。
2. 服务端确定片段所含分镜及相对时间范围。
3. GPT 只根据已确认事实填写每个分镜的四类编辑指令。
4. 服务端验证所有分镜均被覆盖、时间范围合法、固定栏目完整。
5. `replace_product` 模式必须包含产品一致性要求。
6. 不符合结构的模型输出不得标记为 `completed`。

提示词人工保存和 GPT 精修继续创建不可变新版本。精修必须读取用户选择版本的冻结快照，不能漂移到更晚版本。

旧的完整描述提示词继续保留在历史中，但 `prompt_mode` 不是 `reference_video_edit` 时不得用于新的分段生成任务。

版本失效规则：

- 时间轴产生新版本后，旧时间轴的分段方案只能查看，不能创建新提示词或生成任务；
- 分段方案产生新版本后，旧方案对应的提示词和结果继续保留，但旧提示词不能用于新方案片段；
- 提示词产生新版本后，既有生成结果继续保留，新任务必须明确引用用户选择的提示词版本。

## 7. 产品参考图

已确认的产品图片随每个相关生成片段一起提交。图片名称和用途用于形成稳定的参考优先级，例如：

- 正面：正面版式、Logo 位置和主色；
- 侧面：厚度和侧面结构；
- 背面：背标和背部外观；
- 开口：瓶盖、泵头、开口或膏体；
- 细节：材质和局部纹理。

图片文件名不替代人工用途名称。提示词和请求快照应保存用途名称，但不得保存密钥或完整签名 URL。

## 8. 页面设计

不重做现有页面。时间轴确认后增加“生成分段”区域，第五步从“生成并校对完整提示词”调整为“生成并校对编辑指令”，后续接入现有生成与结果能力。

### 8.1 生成分段区域

每段显示：

- 段号、绝对起止时间和时长；
- 包含的分镜范围；
- 切点是否位于分镜边界；
- 是否存在短段或内部切分警告；
- 对应提示词和视频任务状态。

提供自动规划、增加切点、删除切点、移动切点、精确时间切分和恢复自动方案操作。

### 8.2 编辑指令区域

- 按生成片段切换提示词；
- 显示全局保持、替换、删除和禁止规则；
- 显示各分镜相对时间编辑指令；
- 支持 AI 生成、人工保存、指定版本精修和版本恢复；
- 明确显示将随该提示词提交的视频片段和参考图片。

### 8.3 结果区域

每个生成片段显示原始片段播放器、生成结果播放器、提示词版本、任务状态、重试和下载入口。刷新后从数据库恢复，不依赖浏览器本地状态推断任务进度。

## 9. 物理裁切与 Seedance 请求

### 9.1 裁切

- 根据已确认分段方案复用现有 `clip_video()` 的 FFmpeg 重新编码路径生成物理视频片段，不改动现有场景检测、切点吸附和裁切策略。
- 原视频不超过 29 秒时直接使用原文件，不产生无意义副本。
- 超过 29 秒时，为每个生成片段创建可重复定位的本地文件。
- 裁片沿用当前 `-an -c:v libx264 -pix_fmt yuv420p` 行为，因此提交给 Seedance 的分段参考视频不携带原音频；是否生成新音频仍由生成任务的 `generate_audio` 设置决定。
- 裁切失败不得创建供应商任务。
- 输出文件继续经过 FFprobe 验证可解码性和实际时长；不新增“实际裁切起点”数据库字段或帧级校准流程。
- FFprobe 实测时长不得超过有效安全上限。

### 9.2 请求

复用现有 `build_seedance_request` 的请求骨架：

- `text`：当前片段的 `reference_video_edit` 提示词；
- `reference_video`：当前片段的临时公网 URL；
- `reference_image`：该任务需要的产品、人物和背景图片。

每个生成片段只创建一个独立 `Generation`，不为其内部每个分镜创建任务。创建前校验当前分段时长，而不是用原始完整视频总时长直接拒绝。

## 10. 任务恢复与结果

继续复用现有生成状态机：`queued`、`processing`、`retryable`、`submission_uncertain`、`failed`、`completed`。

- 每个片段独立提交、轮询、重试和完成；
- 提交指纹包含分段版本、片段时间范围、提示词版本、供应商、音频设置和参考素材 ID；
- 取得供应商任务 ID 后立即持久化；
- 不明确提交禁止自动重复创建任务；
- 供应商成功后下载到本地临时文件，验证后原子命名；
- 结果验证至少确认文件可解码、存在有效视频流、宽高与帧率为正、时长为正；`generate_audio=true` 时还必须存在音频流；
- 页面刷新、API 重启或 Worker 重启后继续恢复；
- 一个片段失败不得抹掉其他片段的完成结果。

第一版不自动拼接结果。用户可以逐段播放、对比和下载。

## 11. 错误处理

用户可见错误必须区分：

- 分段方案超过安全时长；
- 短片段尚未确认；
- 使用了旧时间轴分段；
- 分镜内部切分风险；
- 物理裁切或 FFprobe 失败；
- 提示词不是参考视频编辑模式；
- 参考素材缺失或未确认；
- Seedance 配置缺失、提交失败、查询失败或结果下载失败。

任何步骤失败都保留原视频、分段方案、提示词历史和其他片段结果。

## 12. 实施阶段

### 实施前置条件

产品图片用途命名已经在 `codex/product-image-labels` 工作树实现，但尚未进入当前 `master`。开始本规格的生产实现前，必须先把该功能安全整合到目标开发分支并通过原有后端、前端、lint 和 build 门槛。本规格复用该实现，不重新开发图片命名。

### 阶段 1：分段模型与算法

- 新增分段版本数据结构和 Alembic 迁移；
- 实现基于镜头边界的 N 段自动规划；
- 实现 29 秒硬限制、8 秒软限制及长镜头内部切分；
- 支持保存、修改和恢复分段方案；
- 增加算法、迁移和 API 测试。

### 阶段 2：提示词方向升级

- 增加 `reference_video_edit` 提示词模式；
- 将完整描述改为“保持、修改、删除、禁止”的固定结构；
- 支持绝对时间到片段相对时间转换；
- 每个生成片段独立生成、保存和精修提示词；
- 验证镜头覆盖、时间范围和固定栏目；
- 保留旧提示词历史并阻止误用。

### 阶段 3：页面接入

- 在现有时间轴流程中增加生成分段区域；
- 支持自动规划、手动段数和切点调整；
- 显示边界吸附、时长和校验错误；
- 第五步改为编辑指令工作区；
- 按片段显示提示词和待提交素材。

### 阶段 4：按生成片段裁切并接入 Seedance

- 根据已确认方案用 FFmpeg 裁出连续物理视频片段；
- 每个物理片段包含一个或多个完整分镜；
- 仅在单个分镜超过 29 秒且无合法边界方案时执行镜头内部切分；
- 将“物理视频片段 + 对应编辑指令 + 参考图”提交 Seedance；
- 每个生成片段创建一个任务，而不是每个分镜创建任务；
- 保留现有幂等、租约恢复、轮询和人工解析机制；
- 移除按完整原视频总时长直接拒绝的逻辑，改为校验实际提交片段。

### 阶段 5：结果闭环

- 按片段恢复和轮询任务；
- 下载并安全保存结果；
- 支持原片段与生成片段对比播放；
- 支持单段重试和下载；
- 刷新后恢复全部状态。

## 13. 测试与验收

### 13.1 分段

- 不超过 29 秒的视频保持单段；
- 30–60 秒视频通常生成两个合法片段；
- 超过 60 秒视频自动生成 N 段；
- 自动方案优先选择分镜边界；
- 不产生 29 秒加极短尾段的不均衡结果；
- 单镜头超过 29 秒时允许内部切分；
- 手动改变段数和移动切点后仍覆盖完整视频；
- 重叠、空洞、超长和未确认短段被服务端拒绝。

### 13.2 提示词

- 每段只读取其覆盖的已确认分镜；
- 提交文本包含固定四类栏目；
- 相对时间转换正确；
- 所有分镜均被覆盖且不重复；
- 产品替换模式包含产品一致性约束；
- 旧完整描述提示词不能提交新生成；
- 精修来源快照不漂移。

### 13.3 生成闭环

- 一个生成片段只创建一个任务；
- 一个包含多个分镜的片段不会创建逐镜任务；
- 原视频超过 29 秒但各提交片段合法时允许生成；
- 任何实际提交片段超过 29 秒时拒绝；
- 片段文件、提示词和参考图进入正确请求；
- 幂等、租约恢复、不明确提交解析、结果下载继续有效；
- 多个片段状态互不覆盖；
- 页面刷新后恢复分段、提示词、任务和结果。

### 13.4 真实验收

自动化测试、后端完整测试、前端测试、lint 和 build 全部通过后，在用户明确允许消耗 API 额度时执行一次真实 Seedance 分段生成。真实验收至少覆盖一个超过 29 秒、含多个分镜的视频，并核对每个任务都使用正确的物理片段、相对时间提示词和产品参考图。

## 14. 成功标准

- 用户可以接受自动 N 段方案，也可以修改段数和切点；
- 切点默认位于分镜临界点，异常长镜头有明确兜底；
- 提示词保留精确时间，但只描述保持项和变化项；
- 每个生成片段而不是每个分镜对应一个 Seedance 任务；
- 原视频、提示词和参考图共同进入供应商请求；
- 任务可恢复，结果可播放和下载；
- 现有项目、时间轴、提示词历史和生成历史不丢失；
- 第一版无需自动拼接即可形成可实际验收的分段生成闭环。
